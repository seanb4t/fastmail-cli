## Build & Development Commands

This project uses [Task](https://taskfile.dev) (not Make) as the build tool.

```bash
task build              # Build binary to ./bin/fastmail-cli
task test               # Run tests with -race -cover
task test:coverage      # Tests + HTML coverage report
task lint               # golangci-lint run ./...
task lint:fix           # Lint with auto-fix
task mocks              # Regenerate mocks via mockery
task all                # lint → test → build
task tidy               # go mod tidy
task docs:serve         # Serve Zensical docs site locally
```

Run a single test:
```bash
go test -run TestEmailQueryArgs_InMailbox ./internal/jmap/
```

Run a single package's tests:
```bash
go test -race ./pkg/fastmail/
```

## Architecture

### Three Protocol Layer

The CLI wraps three distinct Fastmail protocols, each in its own internal package:

1. **`internal/jmap/`** — JMAP (JSON Meta Application Protocol) for email, mailbox, and masked email operations. The client manages session caching (`sync.RWMutex`), method call batching with back-references, and capability discovery.

2. **`internal/dav/`** — CardDAV/CalDAV (WebDAV-based) for contacts and calendar. Returns domain types (`Contact`, `Event`), hiding vCard/iCalendar parsing from consumers.

3. **`mcp/`** — MCP server (stdio JSON-RPC 2.0) exposing Fastmail operations as tools and resources for AI agents. Uses URI templates like `fastmail://mail/{id}`.

### Layering: Internal → Public → CLI

```
cli/          ← Cobra commands, calls pkg/fastmail
pkg/fastmail/ ← High-level service API (Client → MailService, ContactsService, etc.)
internal/     ← Protocol implementations (jmap, dav), auth, config, output formatting
```

The public API (`pkg/fastmail`) hides all protocol details. Consumers interact with domain types (`Email`, `Contact`, `MaskedEmail`, `Event`) through a service pattern:

```go
client := fastmail.NewClient(endpoint, accessToken)
client.Connect(ctx)
emails, err := client.Mail().List(ctx, ...)
```

### Auth & Config

- **Auth**: `internal/auth/` — keychain-first credential storage with file fallback. `AuthStatusError` type carries exit codes (0/1/2/3).
- **Config**: `internal/config/` — Viper-based. Priority: `FASTMAIL_*` env vars > `~/.config/fastmail-cli/config.yaml` > defaults.

## Conventions

- **Errors**: Use `samber/oops` for structured errors with context: `oops.Wrapf(err, "context")`.
- **Testing**: Table-driven tests with `testify/assert` and `testify/require`. HTTP mocking via `httptest.NewServer` or `mockRoundTripper`. Mocks generated by `mockery` (config in `.mockery.yaml`, output to `internal/mocks/`).
- **Dependency injection**: `ClientOption` functional options pattern (e.g., `WithHTTPClient` for testability).
- **Linting**: Strict `.golangci.yaml` — includes `gosec`, `errorlint`, `noctx`, `revive` with many rules. Complexity limits: gocognit=20, gocyclo=15. Tests are exempt from `dupl`/`gocognit`/`gocyclo`/`goconst`.
- **Imports**: `goimports` with local prefix `github.com/seanb4t/fastmail-cli`.
- **CLI**: Cobra-based. Global flags `--config`, `--json`, `--quiet`. Version set via ldflags.
